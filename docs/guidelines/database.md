# Database

Postgres is the transactional database, hosted on Neon. It is the system of
record; anything else — a cache, a search index, a queue — is derived and
disposable.

## No ORM

Queries are written in SQL, by hand. No Prisma, no Drizzle, no TypeORM, no
query-builder DSL.

The reason is not purity: an ORM hides the query that actually runs, so the
plan, the index usage, and the round-trip count all become invisible at the
call site. Hand-written SQL is the thing being executed.

A thin, typed query *client* is expected and welcome — it takes a parameterized
SQL string and returns rows. That is a driver, not an ORM.

## Parameterized always

Every value goes through a placeholder. Never concatenate or interpolate a
value into SQL, whatever its source.

```ts
// wrong — injectable, whatever the type says
await sql(`SELECT * FROM users WHERE email = '${email}'`);

// right
await sql("SELECT id, email FROM users WHERE email = $1", [email]);
```

Identifiers cannot be parameterized. If a table or column name must vary,
select it from a fixed allowlist in code — never from input.

## Rows are external data

A query result is `unknown` until parsed. Parse every row with a schema at the
query boundary and return typed values — see
[data-boundaries](./data-boundaries.md). The database's shape and your type
declaration drift the moment a migration lands; the schema is what catches it.

Keep each query in a named module-scoped function beside its schema, so the SQL,
the parameters, and the result type are one readable unit.

## Query rules

- **Never `SELECT *`.** Name the columns. `SELECT *` breaks silently when a
  migration adds or reorders a column, and it fetches data you do not use.
- **Scope by the authenticated principal in the `WHERE` clause**, not in
  application code after the fetch — see [security](./security.md).
- **No N+1.** One query returning a joined or aggregated result beats a loop of
  queries. If you are iterating and awaiting, stop.
- **Paginate every unbounded list**, with keyset pagination over `OFFSET` for
  anything that grows.
- **Index what you filter, join, and sort on.** Add the index in the same
  change as the query that needs it, and check the plan with `EXPLAIN` when the
  query is not trivially indexed.

## Transactions

Wrap multi-statement writes that must succeed or fail together in one
transaction. Keep transactions short and do no network I/O inside one — never
call an external API mid-transaction.

Make writes idempotent where a retry is possible: `ON CONFLICT DO NOTHING`,
`ON CONFLICT DO UPDATE`, or a natural unique key.

## Connections on serverless

Serverless functions multiply connections fast, and Postgres has a hard limit.

- Use Neon's pooled connection string for request-path queries; use the direct
  connection only for migrations and long-lived jobs.
- Create the client once per module, not per request.
- Set a statement timeout so a pathological query cannot hold a connection.

## Schema conventions

- `snake_case` for tables and columns; plural table names.
- `timestamptz` for every timestamp. Never a naive timestamp, never a local
  time zone.
- Every table has a primary key. Prefer a UUID generated by the application
  when the id is exposed to clients.
- `NOT NULL` by default; nullable is a deliberate choice you can justify.
- Foreign keys with explicit `ON DELETE` behavior — say what happens rather
  than leaving orphans.
- Money is an integer of minor units, or `numeric`. Never a float.
